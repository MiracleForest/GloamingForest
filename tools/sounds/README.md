# tools/sounds: the synthesizer (contract "synth", unit F3)

The Twilight Forest's sounds and music are All Rights Reserved: GloamingForest never opens, decodes
or copies them (rule R10). Every one of TF's 328 sound events is rendered here from **recipes**
by a procedural synthesizer and an Ogg Vorbis encoder written for this project
(`src/core/synth`, standard C++ only, gtested in `tests/synth`). Where TF itself plays a vanilla
Java sound, the event refers to the Bedrock vanilla sound of the same name instead (it is in every
client's vanilla pack and is never copied).

```powershell
pwsh tools/sounds/synth.ps1                      # render every owner into assets/gen/audio
pwsh tools/sounds/synth.ps1 -Unit fauna          # one owner (unit id or name)
pwsh tools/sounds/synth.ps1 -Check               # CI: every event covered and TF's, output byte-identical
pwsh tools/sounds/synth.ps1 -Preview -Event 'entity.twilightforest.raven.*'   # .wav previews in %TEMP%\gf-synth-preview
```

The renderer (`tools/sounds/cli/SynthCli.cpp` + `src/core/synth/*.cpp`) is compiled with clang-cl on
first use into `%LOCALAPPDATA%\gf-synth\<hash>\` (one compiler process, a few seconds). Rendering
everything takes seconds. Output never depends on the machine, the path or thread scheduling:
the synthesizer uses its own math functions (no C runtime transcendental) and seeded random numbers.

Sound definition keys are TF's event names (`entity.twilightforest.naga.hiss`); `gf::fx::sound`
plays them by that name.

## Recipes

A unit refines its own events (docs/spec/owners.tsv, kind `sound_event`) in
`tools/sounds/recipes/<unit>.json`, then runs `pwsh tools/sounds/synth.ps1 -Unit <unit>` and
commits the recipe and `assets/gen/audio/<unit>/` (all of it, `aliases.json` included). Nothing
else changes: a unit's output depends only on its own recipes, the shared patches and the tracks,
so `pwsh tools/sounds/synth.ps1 -Check` (CI) passes after a `-Unit` render. Look at
`tools/sounds/baseline/<unit>.json` for the current definitions; copy an event or a file and change
it.

**Keep TF's variants.** Every definition must match TF's inventory
(`tools/sounds/baseline/inventory.json`): as many variants as TF's event plays, each with TF's
`volume`, `pitch` and `stream` (in any order), TF's `subtitle` key and the `category` of TF's
`SoundSource`. `synth.ps1` fails on any difference (and the `synth.definitions` selftest checks the
assembled pack against `src/feature/ext/synth/SoundEvents.inc`). Refine the sound itself: the
patches, parameters, seeds, files and synthesized stand-ins. A mistake in the inventory (a TF call
site with another source, say) is fixed in `tools/sounds/categories.json` /
`baseline/generate.ps1` by F3 or A8.

**Aliases.** A variant `{"event": id}` plays every variant of another event, its `volume` and
`pitch` multiplied (Java's rule; `stream` if either streams). When that event belongs to another
owner, its sounds are copied into your tree (`sounds/twilightforest/<unit>/alias/<owner>/...`) as
rendered from the owner's recipe at your last render, and `assets/gen/audio/<unit>/aliases.json`
records the copy. `synth.ps1 -Check` renders your copy from that snapshot, so another owner's
change never breaks your check; it prints a **warning** (a GitHub annotation in CI) for each copy
that is older than the owner's current recipe. The aliasing unit refreshes its copies with
`synth.ps1 -Unit <unit>`, and A8's full render (`synth.ps1` without `-Unit`) refreshes all of them.
`synth.ps1 -Unit <owner>` lists the units whose copies the change leaves behind. In TF only the
parrot imitations (U16 `fauna`) play other owners' events.

```jsonc
{
  "patches": { "naga/hiss": { /* a unit-local patch, see below */ } },
  "files": {                                    // rendered sound files, shared by events
    "mob/naga/hiss1": {"patch": "creature/hiss", "params": {"len": 0.9}, "seed": 7, "rate": 44100, "quality": 0.4},
    "music/radiance": {"track": "radiance"}
  },
  "events": {
    "entity.twilightforest.naga.hiss": {
      "category": "hostile",                    // ambient block bottle bucket hostile music neutral player record ui weather
      "subtitle": "subtitles.twilightforest.entity.naga.hiss",
      "max_distance": 16,                       // optional, also min_distance
      "variants": [
        {"file": "mob/naga/hiss1"},                                  // a file above
        {"patch": "creature/hiss", "params": {"len": 1.2}, "seed": 3, "volume": 0.8, "pitch": 1.1},  // rendered inline
        {"vanilla": "sounds/mob/slime/small1"},                      // a Bedrock vanilla sound
        {"event": "entity.twilightforest.naga.hurt", "pitch": 0.9}   // every variant of another event
      ]
    }
  }
}
```

Variant fields `volume`, `pitch`, `weight`, `stream`, `is3D` and `load_on_low_memory` go to
`sound_definitions`; so do the event's `category`, `subtitle` (the closed caption key, shown by
Bedrock's "Closed Captions" option; the text comes from the imported lang files) and
`min_distance` / `max_distance`. Files render mono (3D sounds must be mono) at `rate` (default 44100) with
Vorbis `quality` 0..1 (default 0.4; music 0.25 at 22050).

## Patches

A patch renders one sound. Numbers may be expressions over its parameters: `"$pitch*2"`,
`"semi(-3)"` (semitone ratio), `"hz(69)"` (MIDI to Hz), `"db(-6)"`, `"rand(0.9,1.1)"`,
`"irand(1,4)"`, `"choose(1,2,4)"`, `min max clamp abs floor round exp log sqrt lerp`, `+ - * / ^`.
`rand` draws from the render's seed: variants of a patch differ by seed and every render is
reproducible.

```jsonc
{
  "params": {"pitch": 300, "len": 0.5},        // defaults; recipe params override (and may use $defaults)
  "length": "$len",                            // seconds of the gate
  "tail": 0.25,                                // extra seconds rendered for releases and effects
  "layers": [ { /* layer */ } ],
  "fx": [ {"type": "reverb", "room": 0.5, "damp": 0.5, "mix": 0.2} ],
  "normalize": -1,                             // peak dBFS (false: keep the level), then "gain" dB
  "fade": 0.005                                // fade-out at the end (s); trailing silence is trimmed
}
```

Layer types (`"type"`):

| Type | Keys |
|---|---|
| `osc` | `wave` sine/saw/square/triangle/pulse, `freq`, `pw`, `phase`, `vibrato {rate, depth (semitones), delay}`, `unison {voices, detune (cents)}` |
| `noise` | `color` white/pink/brown/blue, `hold` (Hz sample-and-hold) |
| `fm` | `freq`, `ratio` or `modFreq`, `index`, `feedback`, `wave` |
| `pluck` | Karplus-Strong: `freq`, `decay` (s to -60 dB), `bright` 0..1 |
| `modal` | struck object: `freq`, `modes` (preset wood/metal/glass/bell/stone/bone/ice/drum or `[[ratio, decay, gain], ...]`), `decay` scale, `spread`, `strike` (s of noise) |
| `grains` | grain cloud: `density` (grains/s), `grain` [min, max] s, `freq` [lo, hi], `wave` sine/noise/click, `q`, `grainAmp` |
| `patch` | another patch: `patch` (name or object), `params` |

Common layer keys: `start`, `length`, `amp`, `gain` (dB), `env` (`{a, d, s, r, curve}` ADSR or a
value curve), `ring` (extra seconds for pluck/modal), `tremolo {rate, depth}`,
`filter` (list of `{type lp/hp/bp/notch/peak/bell/lowshelf/highshelf/allpass, freq, q, gain, stages}`),
`formant {vowel (a e i o u, or a 0..4 value that morphs), shift, q, mix}`, `drive`,
`crush {bits, rate}`, `repeat {count, every, jitter, decay}` (re-renders the layer with fresh
`rand` draws).

Time-varying values (any of `freq`, `amp`, `pw`, `index`, `density`, filter `freq`/`q`, `vowel`):
a number or expression; `{"env": [[t, v], ...], "curve": "lin|exp|smooth|step", "rel": false}`;
`{"from": a, "to": b, "curve": "exp", "time": T, "delay": D}`;
`{"lfo": "sine|tri|square|saw|noise|smooth", "rate", "depth", "center": value}`;
`{"mul": [values]}` / `{"add": [values]}`.

Effects (`fx`): `reverb {room, damp, mix, predelay}`, `echo {time, feedback, mix, damp}`,
`chorus {rate, depth, delay, mix}`, `drive {amount}`, `filter {filter, freq, q, gain, stages}`,
`crush {bits, rate}`, `reverse`, `gain {db}`, `fadein {time}`.

## Music tracks

`tools/sounds/music/<track>.json` (U10) or `tools/sounds/baseline/music/<track>.json`:

```jsonc
{
  "rate": 22050, "quality": 0.25, "seed": 1,
  "bpm": 76, "rpb": 4,                          // rows per beat
  "length": 123,                                // seconds rendered exactly (TF's jukebox length)
  "instruments": {"harp": {"patch": "music/harp", "params": {}, "gain": -10, "velAmp": true}},
  "patterns": {"A": {"rows": 64, "channels": [
      {"inst": "harp", "octave": 0, "gain": 0, "notes": "D4:0.8 . F#4 . | A4+D5 . - . C4@bell ."}]}},
  "order": ["A", {"p": "A", "t": 5}],           // t: transpose in semitones; the order loops
  "fx": [{"type": "reverb", "room": 0.75, "mix": 0.22}],
  "normalize": -2, "fadeIn": 1, "fadeOut": 6
}
```

Cells: `.` continue, `-` note off, `C4` / `F#3` / `Bb2` (C4 = MIDI 60), `C4+E4+G4` chord, `:0.7`
velocity, `@inst` instrument override; `|` is ignored (bar lines). A note lasts until the next
cell of its channel. Each note renders its instrument patch with the parameters `freq`, `note`,
`vel` and `dur` (seconds).

## Baseline

`pwsh tools/sounds/baseline/generate.ps1` (needs the TF checkout, `tools/tf/fetch.ps1`) rebuilds the
baseline recipes, `baseline/inventory.json` and `src/feature/ext/synth/SoundEvents.inc` from TF's
`sounds.json` and entity classes: every TF file becomes a synthesized file designed from its name
(one variant per TF file, 226 referenced of TF's 229 `.ogg`; `kobold/shorfle`, `mosquito/mosquito`
and `ur_ghast/trap_active` belong to no event); TF's per-entry volume, pitch and stream flags are
kept on every variant, including event references (the parrot imitations: pitch 1.8, volume 0.6)
and each Bedrock file of a vanilla event (the fortification shield's blocked hit: volume 0.5);
vanilla references map through `vanilla.json` (Bedrock's own file where it has one, otherwise a
synthesized stand-in, e.g. the zombie's iron-door bang `mob/zombie/metal1-3`); the subtitle key is
TF's; the category is the Bedrock counterpart of the `SoundSource` TF plays the event with
(`categories.json`: explicit call sites, then `block.*` block, `item.*` player, mob sounds the mob's
own source from its class: HOSTILE for monsters, NEUTRAL otherwise). The inventory is a separate
flattening of TF's `sounds.json`, not of the recipes. `baseline/compose.ps1` writes the placeholder
tracks. Both have `-Check`.
